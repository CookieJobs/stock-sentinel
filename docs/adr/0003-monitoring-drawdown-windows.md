# ADR-0003: 监控回撤采用可切换窗口，提醒固定一年

> 状态: ✅ 已采纳
> 日期: 2026-08-28
> 决策者: 项目所有者 + AI 协作

## 背景

监控页原本将不同数据源返回的历史样本都称为「52 周」，用户无法得知回撤从何时开始，也无法在短、中、长期研究节奏间切换。若让风险提醒跟随页面窗口，已保存的阈值和告警状态会随一次浏览操作改变含义。

## 决策

1. 使用滚动日历窗口 `3m`、`6m`、`1y` 计算监控回撤；窗口起点为当前日期往前对应自然月的同日，起止日均包含。
2. 所有市场以标准化后的日线高低点计算同一公式；起点后超过 3 个自然日仍缺少历史时返回 `insufficient_history`，不返回数值。
3. 在 `stocks` 和 `price_history` 增加 JSON 快照 `drawdown_windows`；前端切换仅切换本地已保存数据与历史 API 的窗口参数，不额外请求行情源。
4. 保留既有 `week52_*`、`drawdown` 和 `distance_low_pct` 字段，但它们仅映射 `1y` 窗口，供提醒、简报和兼容接口使用。
5. 告警阈值和状态机始终读取固定 1 年字段。页面的 3/6/1 年切换只改变研究视图。

## 备选方案

### 仅保留 52 周，补一段说明

否决：不能解决跨数据源样本长度不一致，也无法满足短中期研究需求。

### 让提醒跟随页面选择

否决：一次查看 3 个月数据就会改变长期风险线的含义，容易产生意外提醒或漏提醒。

### 每只股票保存独立的提醒周期

否决：当前核心需求是可靠地浏览比较，而非增加提醒策略复杂度；后续若需要可单独设计。

## 后果

- ✅ 表格、统计、趋势和导出可以明确引用同一时间窗口。
- ✅ 数据不足与存量历史数据会被显式标记，不会伪装成完整的一年回撤。
- ✅ 已有提醒语义保持稳定，SQLite 迁移仅新增列，不改写用户数据。
- ⚠️ 日线数据需要覆盖约 1 年；初次刷新或数据源失败时，监控页会显示「数据不足」。
