# ADR-0002: 数据源策略（多源 fallback）

> 状态: ✅ 已采纳
> 日期: 2026-06-02 (M0 阶段)
> 最近更新: 2026-06-03 (BaoStock 加入调研)

---

## 背景

量化平台**严重依赖实时 + 历史数据**：
- K 线（实时 + 多年历史）
- 财务数据（PE / PB / ROE / 净利润）
- 行业 / 概念板块
- 指数（基准对比）

用户明确要求**纯免费**，且**单 IP 频率限制**是个核心问题（东方财富/AkShare 都限流）。

---

## 决策

### 1. 多源 + 优先级 fallback
每种数据**至少 2-3 个源**，按优先级逐个尝试，任一成功即用。

```
K 线:
  优先级 1: 东方财富 (eastmoney)
  优先级 2: AkShare
  优先级 3: 本地 SQLite 缓存

因子 / 财务:
  优先级 1: Tushare (200 积分档, 最稳)
  优先级 2: AkShare (免费, 限流)
  优先级 3: BaoStock (限流但数据全)
  优先级 4: Mock (开发演示)

美股 / 港股:
  优先级 1: Tushare
  优先级 2: Finnhub (60次/分)
  优先级 3: (yfinance 2024-2025 已失效, 跳过)
```

### 2. 抽象层 `data_source/`
- 统一接口：`get_kline(ticker, market, period, start, end, adj) -> pd.DataFrame`
- 统一列名：`trade_date, open, high, low, close, volume, amount`
- 数据源插件化，新增源只需写一个新类

### 3. 本地缓存 + 持久化
- K 线入库（`kline` 表）—— 拉过的就别再拉
- LRU 内存缓存（5 分钟 TTL）
- 智能判断 stale：日 K 1 天内不重新拉

### 4. yfinance **不可用**（2026-06-03 调研确认）
- 2024-2025 Yahoo Finance 严限非官方 API
- yfinance 1.4.x **每次调用 Rate Limited**
- 老版本 0.2.40 也跑不通
- **不能用 yfinance**（**已推翻 2026-06-02 路线图建议**）

---

## 备选方案

### 方案 A: 单源 + 高频重试
只用 Tushare（200 积分）或 AkShare，加重试和退避。

**否决理由**：
- 单源单点故障
- 高频触发对方限流
- 重试可能 1-3 分钟才返回

### 方案 B: 全付费（Wind / 通联）
**否决理由**：
- 几万到几十万/年
- 个人工具不划算
- 项目所有者明确说"纯免费"

### 方案 C: yfinance
**否决理由**：
- 2024-2025 已实质失效
- 看似无敌但实际跑不通

---

## 后果

### 好的
- ✅ 单源失败时**自动降级**，不阻塞用户
- ✅ 本地缓存减少**网络依赖**
- ✅ 新源接入简单（一个类即可）

### 代价
- ⚠️ 数据源层代码量翻倍（每源 50-200 行）
- ⚠️ 测试环境很难验证所有源（IP 限流）

## 经验

1. **多源 fallback 必要** —— 单源单点故障
2. **数据源限制在测试环境更严** —— 实际生产需评估
3. **yfinance 2024-2025 已失效** —— 别相信"看起来免费无敌"
4. **Tushare 至少 200 积分** —— 100 不能用
5. **本地缓存 + 入库** 是性能关键
