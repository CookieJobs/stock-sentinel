# 回测新手引导与名称选股设计

## Context

回测页当前将策略实现、参数、代码、成本和基准并列为同一级输入。它适合知道量化术语的人，却没有回答首次用户最先关心的两个问题：我要测一只股票还是一组股票？我如何找到这只股票？

## Chosen Approach

采用单一页面的渐进揭示，而非拆出“新手版”和“专业版”。默认界面只有完成首次回测必需的决策；展开高级设置后，用户操作同一份真实表单和同一个回测引擎。

这比两个独立页面更容易维护，也避免新手获得功能受限的版本、专家被迫切换上下文。它比保留原表单并添加帮助文案更有效，因为交互顺序本身被改成了用户意图。

## Interaction Design

### 1. 选择回测方式

页面标题下显示两个可访问的选择按钮：

- `跟随趋势`：说明为“回测一只股票，在短期趋势强于长期趋势时持有”。映射到 `ma_cross`、`fast=5`、`slow=20`、`rebalance_freq=none`。
- `等权持有`：说明为“把多只股票平均分配，按月恢复相同仓位”。映射到 `equal_weight`、`rebalance_freq=monthly`。

当前选项使用现有蓝色语义色和 `aria-pressed` 表达状态。模式切换不清空已经选中的标的，只在提交时验证数量。

### 2. 选择标的

搜索输入放在“选择股票”步骤中，提示“输入股票名称、拼音或代码，例如：茅台、MAOTAI、600519”。输入后 300ms 发起已有 `search.stocks` 请求。候选项展示名称、代码和市场；点击或按 Enter 选择。无候选的直接代码仍可按 Enter 添加，确保网络降级时可用。

已选股票显示为名称优先的标签，带代码、市场和删除按钮。第一个选择锁定该次回测市场；尝试加入其他市场的标的时显示行内错误。回测引擎只接受单一市场，该约束必须在提交前解释。

### 3. 时间与执行

默认回测窗口为截至今天的最近一年，避免旧的固定 2024 日期。提交前在按钮上方显示简明摘要，例如“用趋势方式回测贵州茅台，2025-08-27 至 2026-08-27，对比沪深300”。主按钮使用“运行回测”。

### 4. 高级设置

原有名称、策略、策略参数、初始资金、基准、调仓频率、手续费与滑点放入原生 `<details>`。高级策略选择仍可改为 `factor_rank` 或 `fixed_weights`，现有 API 不变。每个原始英文策略和参数配以中文说明，专业用户仍能看到实际值。

策略模板被保留为“尝试现成方案”，放在主流程之后，避免首次用户误以为必须先理解模板。历史结果和运行中状态保持原位置与行为。

## Data Flow and Errors

新增 `frontend/src/lib/backtest-flow.js`，集中处理可测试的模式默认值、按 `(market, ticker)` 去重、同市场验证和 API payload 构建。React 页面持有搜索、选择和 UI 状态，仍通过现有 `backtest.run` 和 `search.stocks` API 通信。

错误在相关步骤下方用文字说明，且保留现有颜色提示：没有标的、单股模式标的数量不为一、组合少于两只，以及混合市场。搜索失败时清空候选但允许有效代码直接添加。

## Verification

使用 Node 内建测试框架覆盖流程函数。浏览器检查名称搜索、键盘回车、标签删除、模式校验、同市场限制和高级设置；随后执行 lint 与生产构建。后端不变，只运行相关 API 回归；完整后端套件若仍因 Tushare 在受限目录写入 `~/tk.csv` 失败，记录为环境基线问题。
